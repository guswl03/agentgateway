# 정책 가져오기와 검토 화면

`/ui/policy-import`에서 정책 팩을 선택하고 각 요구사항의 서비스 적용 여부와 이행 근거를 검토한 뒤 Gateway 설정 후보를 확인한다.

1. 검토 범위 선택: 기본 의료법·AI 기본법·개인정보 보호법 팩을 함께 선택하거나 다른 팩을 업로드한다.
2. 정책별 판단과 근거: 검색·상태 필터 목록에서 정책을 선택하면 상세 패널에 요구사항과 입력란을 표시한다. 적용·미적용·판단 전 버튼은 한 번에 선택하고 목록에 저장 전 상태를 표시한다. 입력한 이유·담당자·근거를 판단 기록 저장 버튼으로 확정한다. 항목 이동과 검색에서 임시 입력을 유지하고 새 소스를 불러오면 초기화한다.
3. 설정 확인과 적용: 기능 선택, 서비스 적용 판단, 설정 생성, 관리자 검증 기록을 구분한다. 필요한 판단·설정·증거가 누락되거나 후보가 변경되면 이 화면의 적용을 차단한다. 0개 활성 기능도 적용하지 않는다. 검토 파일과 후보 YAML은 별도로 내려받을 수 있다.

미적용으로 기록하면 해당 카드의 이번 Gateway 기능 선택을 해제한다. 기존 실행 정책을 제거하려면 하단 기존 설정 관리 영역에서 별도로 처리한다. 등록 증거는 관리자가 작성한 기록이며 법률 준수 인증이 아니다. 이 UI의 준비 상태 검사는 일반 관리자 API 전체에 대한 서버 강제 검증을 대체하지 않는다.

이 저장소의 최신 main에는 정책 가져오기 기능이 없어 `bobkise/mvp1`의 정책 팩·커넥터·어댑터, hybrid 설정 저장, FHIR 필터 및 실행 정책 근거 표시 코드도 함께 이식했다. 기존 main의 대시보드 변경은 보존한다. 부트스트랩·배포 도우미 등 mvp1의 별도 기능은 이식하지 않았다.

커넥터 실행 환경에 Python 3이 필요하다. `AGENTGATEWAY_POLICY_PYTHON`으로 실행 경로를 지정할 수 있다. 정책 자료와 커넥터는 바이너리에 포함되며 `src/policy` 외부 디렉터리를 필요로 하지 않는다. Docker 실행 이미지에도 Python을 설치한다.

## 검증

`ui/`에서 `pnpm build`, `pnpm test:policy`, `pnpm test:policy-ui`를 실행한다. 브라우저 검사는 설치된 Playwright Chromium을 사용하며, Chrome 사용 시 `PLAYWRIGHT_CHANNEL=chrome`을 지정한다.

로컬 검증은 어댑터 182개, Chrome 화면 18개, 타입 검사와 생산 UI 빌드가 통과했다. 화면 검사는 저장 전 상태, 새 소스 초기화, 모바일 입력, 검색·필터, 판단과 기능 선택 구분, 근거 부족·충돌·0개 적용 차단, 파일·DB 저장 경로를 확인한다.

Rust 도구가 없어 Gateway 빌드와 실제 바이너리 검증은 실행하지 못했다. mvp1의 필수 FULL 검사 35개는 빌드 단계에서 BLOCKED이며 위 UI 검사 결과로 대체하지 않는다. 이 변경은 초안 PR로 게시하며 실제 운영 반영 전에 Rust 및 런타임 검증을 완료해야 한다.
